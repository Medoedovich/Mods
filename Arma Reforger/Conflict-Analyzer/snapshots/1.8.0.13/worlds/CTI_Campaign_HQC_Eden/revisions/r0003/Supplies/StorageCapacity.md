# Вместимость хранилищ — SP_A_EveronAirport

## Summary

Версия игры: **1.8.0.13**. Проверена одна база; весь снимок имеет статус **partial**.

Хранилищ: **2**. Физических контейнеров: **5**. Суммарная настроенная вместимость: **4000 припасов**.

## Откуда берутся данные

- Связь база → хранилище → контейнер: родительская иерархия `IEntitySource`, включая вложенные prefab.
- Состав: `SCR_ResourceComponent.m_aContainers`; учитываются физические `SCR_ResourceContainer` с `m_eResourceType=SUPPLIES`.
- Вместимость: `m_fResourceValueMax`. Начальное количество: `m_fResourceValueCurrent`, отдельное поле конфигурации.
- Сумма: вместимости уникальных слотов `(sourceId, componentIndex, containerIndex)`. Виртуальные `SCR_ResourceContainerVirtual` не прибавляются повторно.
- Название: source name; если пусто — имя файла prefab. Автоматические подписи редактора с суффиксом экземпляра этим API не получены.

## Ограничения

Виртуальных представлений исключено из суммы: **2**. Компоненты базы и указателей без физических контейнеров не являются дополнительными хранилищами.

Это вместимость заданных в мире физических контейнеров под выбранной базой. Динамически построенные склады, соседние объекты вне этой иерархии, runtime-связи ресурсной сети и изменение состояния при запуске не исследованы. Отключённые контейнеры сохраняются как конфигурация, их состояние указано в JSON.

Значения могут наследоваться или быть заданы по умолчанию. Точный ресурс определения поля пока unknown; ближайший prefab не подменяет его. JSON сохраняет исходные поля и признаки override.
