# Строительство и разрушение

Приоритет направления: **P1**. Статус: **Запланировано**. Категория: `building`.

[Все направления](README.md) · [Общий формат и правила](../LOGGING_SPEC.md)

Цель — восстанавливать изменения построек и установленных объектов, отделяя действие игрока от неизвестного разрушения.

## События и приоритет реализации

| Событие | Приоритет | Статус | Когда записываем |
|---|---|---|---|
| `building.object_placed` | P1 | Запланировано | После фактической установки объекта в мире |
| `building.part_built` | P1 | Запланировано | После завершённого строительства части конструкции |
| `building.part_dismantled` | P1 | Запланировано | После завершённого разбора части |
| `building.part_destroyed` | P1 | Запланировано | После подтверждённого разрушения части |

## Данные событий

| Контекст | Данные сверх общего конверта |
|---|---|
| Объект | Тип, ID сущности с областью действия, позиция |
| Часть | Идентификатор/название части и состояние до/после |
| Действие игрока | Инструмент, известные фактически потраченные/полученные материалы |
| Разрушение | Наблюдаемый источник, средство и связь с уроном, если подтверждены |

Объект строительства находится в `target`. При разрушении без достоверного игрока-инициатора использовать `actor: null`. Владелец базы и инициатор изменения — разные сведения; владение не выводится из близости игрока к объекту.

## Работы по этапам

| Работа | Приоритет | Критерий готовности |
|---|---|---|
| Установка объекта | P1 | Записывается конечный объект, а не каждый предварительный показ места установки |
| Постройка и разбор части | P1 | Известны объект и часть, а результат подтверждён сменой состояния |
| Разрушение и источник | P1 | Разбор не считается разрушением; неизвестный инициатор не угадывается |
| Материалы и контекст территории | P2 | Есть проверенный источник количеств/владения, указана интеграция |

## Правила и проверки

- Отмена установки/строительства без изменения мира не создаёт событие результата.
- Одна постройка может породить переносы материалов: это отдельные факты, их можно связать через `correlation_id`.
- Удаление объекта очисткой мира не выдавать за разрушение игроком; при неизвестной причине хранить `unknown`.
- Проверить установку объекта, строительство, разбор, разрушение игроком/взрывом, смену объекта и повторные callback.

Зависимости: [инвентарь](inventory.md) для материалов, [бой](combat.md) для контекста урона. Представления — история объекта, изменения базы и места разрушений. Вывод «рейд» остаётся результатом анализа, а не названием любого разрушения.
