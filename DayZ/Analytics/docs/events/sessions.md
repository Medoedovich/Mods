# Игровые сессии

Приоритет направления: **P0**. Статус: **Запланировано**. Категория: `session`.

[Все направления](README.md) · [Общий формат и правила](../LOGGING_SPEC.md)

Цель — фиксировать границы присутствия игрока и связывать его действия в одну сессию.

## События и приоритет реализации

| Событие | Приоритет | Статус | Когда записываем |
|---|---|---|---|
| `session.player_connected` | P0 | Запланировано | При подтверждённом успешном подключении, когда известна личность игрока |
| `session.player_disconnected` | P0 | Запланировано | При завершении активного подключения |

## Данные событий

| Контекст | Данные сверх общего конверта |
|---|---|
| Подключение | Новый `session_id`, известный ID аккаунта, имя; Steam64 отдельным полем при доступности |
| Отключение | Тот же `session_id`, известная причина, последняя позиция и `position_time_utc` |
| Связь с персонажем | `life_id`, только если установлен достоверно; иначе `null` |

Игрок находится в `actor`; цель обычно отсутствует. Позиция при подключении может быть ещё неизвестна — координаты появятся в событии персонажа.

## Работы по этапам

| Работа | Приоритет | Критерий готовности |
|---|---|---|
| Выдача ID и подавление повторных callback входа/выхода | P0 | Один вход и один выход на подтверждённое подключение |
| Сохранение контекста до удаления объекта игрока | P0 | При выходе доступны ID и последняя позиция с временем её получения |
| Причины выхода | P0 | Сохраняется известная причина; неподтверждённая — `unknown` |
| Длительность и возвращаемость в инструментах | P1 | Считаются по событиям, незавершённые сессии показаны отдельно |

## Правила и проверки

- Переподключение создаёт новую сессию; сохранённый персонаж может продолжать прежнюю жизнь.
- Попытка входа без успешного подключения не создаёт полноценную сессию P0.
- После аварии сервера нельзя выдумывать время отключения; завершение сессии показывается как неизвестное.
- Проверить повторные callback, обычный выход, обрыв соединения, переподключение, рестарт и отсутствие объекта игрока на момент выхода.

Зависимости: [служебные](system.md), связь с [персонажем](character.md). Представления — история посещений и хронология игрока.
