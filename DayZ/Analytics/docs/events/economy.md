# Экономика

Приоритет направления: **P2**. Статус: **Запланировано**. Категория: `economy`.

[Все направления](README.md) · [Общий формат и правила](../LOGGING_SPEC.md)

Цель — фиксировать подтверждённые сделки и изменение счетов через конкретные моды торговли/банкинга. Универсальная доступность таких данных заранее не предполагается.

## События и приоритет реализации

| Событие | Приоритет | Статус | Когда записываем |
|---|---|---|---|
| `economy.trade_completed` | P2 | Запланировано | После подтверждённого завершения покупки/продажи |
| `economy.balance_changed` | P2 | Запланировано | После подтверждённого изменения счёта |

## Данные событий

| Контекст | Данные сверх общего конверта |
|---|---|
| Интеграция | Название/версия источника, известный ID транзакции с областью уникальности |
| Сделка | Покупка/продажа, продавец/покупатель, торговец/контрагент, предметы, количества, итоговая сумма и валюта |
| Счёт | Владелец, ID/тип счёта, баланс до/после, разница, валюта, подтверждённая причина |
| Связь фактов | `correlation_id` или ID транзакции для сделки, счёта и переноса предметов |

В торговле `actor` — известный инициатор; `target` — контрагент/торговец при доступности. При системном изменении счёта инициатор может отсутствовать; владелец счёта указывается отдельно и не выдаётся за инициатора.

## Работы по этапам

| Работа | Приоритет | Критерий готовности |
|---|---|---|
| Адаптер выбранного торгового мода | P2 | Определён источник подтверждения результата и все доступные поля |
| Адаптер счёта/банка | P2 | Различимы владелец, инициатор, валюта и причина |
| Повторные callback и доставка | P2 | Одна операция не считается двумя из-за повторов; повторная доставка сохраняет `event_id` |
| Неполный контекст операции | P2 | Недоступные данные отмечены, списание не объявляется завершённой сделкой без подтверждения |

## Правила и проверки

- Открытие торгового меню и нажатие покупки не равны завершённой сделке.
- Балансовое изменение и сделка могут быть двумя связанными фактами. В отчёте не складывать их как две независимые покупки.
- Проверить покупку/продажу, перевод, отмену/откат, повторный callback, физические деньги, несколько валют и неизвестного контрагента в выбранной интеграции.

Зависимости: [сессии](sessions.md), [инвентарь](inventory.md), отдельный адаптер каждого внешнего мода. Представления — сделки, оборот, счета и источники получения вещей.
