# Лечение и состояние организма

Приоритет направления: **P0**. Статус: **Запланировано**. Техническая категория: `survival`.

[Все направления](README.md) · [Общий формат и правила](../LOGGING_SPEC.md) · [Питание](nutrition.md)

Цель — фиксировать выполненное лечение, его получателя и наблюдаемое состояние организма. Применение лекарства само по себе не доказывает выздоровление.

## События и приоритет реализации

| Событие | Приоритет | Статус | Когда записываем |
|---|---|---|---|
| `survival.treatment_applied` | P0 | Запланировано | По итогу выполненного или частично выполненного лечебного действия |
| `survival.vitals_sampled` | P1 | Запланировано | При настроенном замере состояния, связанном с известным моментом времени |

## Данные событий

| Контекст | Данные сверх общего конверта |
|---|---|
| Лечение | Кто применил, к кому, тип действия, предмет, фактический расход и единица |
| Результат действия | `success` / `partial`, длительность; непосредственное изменение только при доступном наблюдении |
| Состояние | Доступные Health, Blood, Shock, энергия, вода, температура, кровотечения и состояния болезней с единицами |
| Замер | Причина, время и доступность каждого показателя; старые значения не выдаются за текущие |

При самолечении `actor` и `target` обозначают одного игрока. При помощи другому игроку они различаются. Для периодического замера сам наблюдаемый игрок находится в `actor`.

## Работы по этапам

| Работа | Приоритет | Критерий готовности |
|---|---|---|
| Самолечение и лечение другого игрока | P0 | Инициатор и получатель верны; завершённое действие не дублируется |
| Частичный расход при прерывании | P0 | Сохраняется наблюдаемый расход, отмена без эффекта пропускается |
| Периодические показатели организма | P1 | Стартовый интервал 60 секунд, конфигурируемый; нет записи каждого тика |
| Состояние до/после лечения | P1 | У замеров есть время; отложенное изменение не объявляется доказанным эффектом лекарства |

## Правила и проверки

- Потеря сознания и смерть относятся к [персонажу](character.md), входящий урон — к [бою](combat.md).
- Внутри замера отсутствующий показатель — `null`, а не «здоров». Нормализованные и абсолютные значения различаются именами/единицами.
- Проверить перевязку себя/другого игрока, применение лекарства, частичное действие, отмену, исчезновение получателя и замер в момент смерти.
- Поддержку каждого вида лечения подтверждать отдельно; наличие общего события не означает готовность всех действий DayZ.

Зависимости: [сессии](sessions.md), [персонаж](character.md), контекст [инвентаря](inventory.md). Представления — история лечения и состояние до/после происшествия.
