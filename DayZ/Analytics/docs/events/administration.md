# Администрирование

Приоритет направления: **P2**. Статус: **Запланировано**. Категория: `admin`.

[Все направления](README.md) · [Общий формат и правила](../LOGGING_SPEC.md)

Цель — отличать подтверждённые административные изменения от обычных действий игрока и связывать их с известным оператором.

## События и приоритет реализации

| Событие | Приоритет | Статус | Когда записываем |
|---|---|---|---|
| `admin.command_executed` | P2 | Запланировано | После выполнения административной команды с известным результатом |

## Данные события

| Контекст | Данные сверх общего конверта |
|---|---|
| Оператор | Известный ID человека либо системного исполнителя; источник интеграции |
| Команда | Стабильный код действия, относящиеся к изменению параметры, время выполнения |
| Цель | Игрок, объект или сервер; известные ID и позиции |
| Результат | Подтверждённый результат и фактическое изменение, известная причина |

Человек-оператор находится в `actor`, объект действия — в `target`. Системный исполнитель описывается в `data`; отсутствие игрока не заполняется вымышленным аккаунтом.

## Работы по этапам

| Работа | Приоритет | Критерий готовности |
|---|---|---|
| Адаптер выбранного админ-инструмента | P2 | Оператор и результат взяты из подтверждённого источника |
| Связь с последствиями команды | P2 | Телепортация, изменение вещей/здоровья связаны с командой при доступности |
| Различение команды и её эффекта в отчёте | P2 | Одно изменение не считается несколькими выполненными командами |
| Другие административные источники | P2 | Для каждого источника явно указаны поддерживаемые действия и ограничения |

## Правила и проверки

- Запрос команды до проверки/выполнения не является `admin.command_executed`; наблюдение только запроса не подтверждает результат.
- Админ-команда и наблюдаемое последствие могут иметь разные события с общим `correlation_id`.
- [Телепортация](movement.md) фиксируется отдельно при подтверждении; скачок координат не доказывает действия администратора.
- Проверить действие над собой/другим игроком, объектом/сервером, системного исполнителя, повторный callback и отсутствие подтверждённого результата.

Зависимости: отдельная интеграция админ-инструмента и контекст затронутых направлений. Представления — журнал операторов и происхождение административных изменений.
