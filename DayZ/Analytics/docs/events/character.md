# Жизнь персонажа

Приоритет направления: **P0**. Статус: **Запланировано**. Категория: `character`.

[Все направления](README.md) · [Общий формат и правила](../LOGGING_SPEC.md)

Цель — отличать новую жизнь от загрузки сохранённого персонажа и восстанавливать смерть и потерю сознания.

## События и приоритет реализации

| Событие | Приоритет | Статус | Когда записываем |
|---|---|---|---|
| `character.spawned` | P0 | Запланировано | Когда новый или загруженный персонаж появляется в игровом мире |
| `character.died` | P0 | Запланировано | При подтверждённом переходе персонажа в состояние смерти |
| `character.consciousness_changed` | P0 | Запланировано | При переходе между сознанием и бессознательным состоянием |

## Данные событий

| Событие | Данные сверх общего конверта |
|---|---|
| Появление | `spawn_kind`: `new`, `loaded`, `unknown`; позиция, достоверный ID жизни |
| Смерть | Позиция жертвы, подтверждённый источник/убийца, средство урона, последние доступные показатели состояния с временем замера |
| Сознание | Состояния до/после: `conscious` / `unconscious`; наблюдаемый контекст, если доступен |

В событии смерти жертва находится в `target`, подтверждённый убийца — в `actor`. При причине среды или неизвестном инициаторе `actor: null`. В появлении/изменении сознания сам персонаж находится в `actor`.

## Работы по этапам

| Работа | Приоритет | Критерий готовности |
|---|---|---|
| Отличать создание от загрузки | P0 | Переподключение не считается новой жизнью; сомнение обозначено `unknown` |
| Одна смерть на персонажа | P0 | Несколько callback не создают несколько смертей |
| Связь аккаунта, сессии и жизни | P0 | Неизвестный `life_id` остаётся `null`, а не заменяется ID сессии |
| Расширенный контекст перед смертью | P1 | Можно связать последние наблюдения с их временем, не приписывая им причинность |

## Правила и проверки

- Последний попавший игрок не обязательно убийца. Причина смерти без подтверждения — `unknown`.
- Смерть не должна создавать фиктивное «пришёл в сознание» при удалении/смене состояния объекта.
- Проверить новый персонаж, загрузку, респавн, смерть от игрока, заражённого и среды, повторный callback, потерю/возврат сознания.
- ID жизни между сессиями/рестартами сохранять только после проверки надёжного способа восстановления.

Зависимости: [сессии](sessions.md); контекст [боя](combat.md) и [состояния организма](medical.md). Представления — история жизней и карточка смерти.
