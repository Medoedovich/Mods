# Взаимодействия с миром

Приоритет направления: **P1**. Статус: **Запланировано**. Категория: `interaction`.

[Все направления](README.md) · [Общий формат и правила](../LOGGING_SPEC.md)

Цель — фиксировать значимые изменения дверей, контейнеров и тайников, дополняющие историю вещей и построек.

## События и приоритет реализации

| Событие | Приоритет | Статус | Когда записываем |
|---|---|---|---|
| `interaction.open_state_changed` | P1 | Запланировано | После подтверждённого открытия/закрытия поддерживаемого объекта |
| `interaction.stash_changed` | P1 | Запланировано | После фактического закапывания/выкапывания тайника |

## Данные событий

| Контекст | Данные сверх общего конверта |
|---|---|
| Открытие/закрытие | Объект, конкретная дверь/створка при доступности, состояние до/после |
| Тайник | Тип действия, объект до/после, связь ID при замене сущности, инструмент |
| Общий контекст | Позиция объекта, инициатор, известная причина изменения |

Инициатор попадает в `actor` только при подтверждении; объект — в `target`. Для нескольких дверей одного здания идентификатор створки хранится отдельно от ID здания.

## Работы по этапам

| Работа | Приоритет | Критерий готовности |
|---|---|---|
| Настраиваемый список типов объектов | P1 | Можно включить двери/ворота/контейнеры отдельно, без перехвата всех объектов мира |
| Подтверждённое изменение открытого состояния | P1 | Повторное взаимодействие без смены состояния не создаёт новый факт |
| Тайники | P1 | Создание замены объекта связывается с исходным тайником при доступности |
| Дополнительные типы взаимодействий | P2 | Каждое новое событие сначала внесено в каталог, определены польза и объём |

## Правила и проверки

- Чтение содержимого контейнера и перенос вещи — разные факты; перенос описан в [инвентаре](inventory.md).
- Спавн уже открытого объекта при загрузке мира не считается действием игрока.
- Массовые открытия обычных дверей могут давать большой объём: включать типы отдельно и измерить частоту.
- Проверить открытую/закрытую дверь, несколько створок, ворота, контейнер, закапывание/выкапывание и загрузку мира.

Зависимости: [инвентарь](inventory.md), контекст [строительства](building.md). Для баланса рассматриваем агрегированную частоту обоснованных исследовательской задачей взаимодействий. Карта тайников и поиск схрона/запасов конкретного игрока не являются функциями проекта и запрещены [принципами использования данных](../GOALS.md). Детальные эпизоды допускаются только для ограниченной технической диагностики.
