# Предметы и инвентарь

Приоритет направления: **P0**. Статус: **Запланировано**. Категория: `inventory`.

[Все направления](README.md) · [Общий формат и правила](../LOGGING_SPEC.md)

Цель — восстанавливать получение, передачу и потерю вещей и отличать их от внутреннего перекладывания.

## События и приоритет реализации

| Событие | Приоритет | Статус | Когда записываем |
|---|---|---|---|
| `inventory.item_transferred` | P0 | Запланировано | После подтверждённого переноса предмета или его количества |
| `inventory.snapshot_taken` | P1 | Запланировано | При подключении, смерти или явном запросе снимка |

## Данные событий

| Контекст | Данные сверх общего конверта |
|---|---|
| Предмет | Classname, ID сущности с областью действия, количество и единица |
| Откуда/куда | `ground`, `hands`, `cargo`, `attachment`; известный владелец и контейнер каждой стороны |
| Результат | Фактическое изменение, причина при доступности, полнота сопоставления |
| Снимок | Причина, время и список наблюдаемых предметов/слотов/количеств; полнота снимка |

## Работы по этапам

| Работа | Приоритет | Критерий готовности |
|---|---|---|
| Подбор/выбрасывание и перенос в мировой контейнер/из него | P0 | Одна запись на перенос с верными сторонами и количеством |
| Передача между игроками | P0 | Не путаются владелец контейнера и инициатор; неизвестные сведения — `null` |
| Стаки, начальная загрузка и подавление дублей | P0 | Деление/объединение не считается несколькими новыми получениями лута |
| Снимки инвентаря | P1 | Нет постоянного полного обхода, причина и полнота снимка известны |
| История одного предмета между рестартами | P2 | Используется только проверенный постоянный ID; runtime ID не связывает разные запуски |

## Правила и проверки

- Перекладывание между собственными карманами по умолчанию пропускается; перенос через границу владения/мирового контейнера сохраняется.
- Если инициатор переноса не известен, не считать нового владельца автоматически инициатором; заполнять владельцев в `from`/`to`.
- Стартовая загрузка вещей не является подбором. Предметы на трупе не являются добровольно выброшенными вещами.
- Если несколько callback нельзя надёжно свести к одному переносу, пометить контекст как `partial`, не выдумывать количество.
- Проверить землю, руки, карманы, контейнер, передачу, стаки, подключение, смерть и дальнейшее снятие вещей с трупа.

Зависимости: [сессии](sessions.md), [персонаж](character.md). Потребление, крафт и торговля имеют свои смысловые события; связывать их переносы через `correlation_id` при доступности. Представления — история вещей и источники полученного лута.
