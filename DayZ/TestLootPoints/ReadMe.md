# Поиск проблемных точек лута

Памятка для одиночной тестовой миссии `test.dayztestrange` в DayZDiag. Цель — воспроизвести неправильное размещение предмета, найти соответствующую точку и проверить исправление.

## Алгоритм проверки

1. **Определить здание и предмет.**
   Записать classname здания и проблемного предмета, например `Land_Store_Street1` и `Hammer`. Зафиксировать, что наблюдается: предмет частично под полом, полностью проваливается или висит над поверхностью.

2. **Определить точку лута.**
   Найти её контейнер и локальные координаты в `mapgroupproto.xml`. В Diag Menu ориентироваться на нижний блок **SELECTED** и значение **Rel**. Верхний блок **EDIT** показывает текущую позицию редактирования под курсором. Сохранить исходные `pos`, `range`, `height` и `flags`, если они указаны.

3. **Воспроизвести случай через CE.**
   Для однозначного теста использовать одну точку и один тип предмета. В `db/types.xml` оставить нужный предмет с `nominal=1`; лимиты группы и контейнера для такого теста — `lootmax=1`. Проверить совместимость категории, usage и тегов предмета с контейнером. Перед сокращением исходного набора сохранить его копию.

4. **Менять по одному параметру точки.**
   Например, сначала изменить только Y в `pos`. Затем отдельно проверять размер области `range` и другие параметры, если это нужно. После удаления и создания точки заново сравнить все параметры: могли измениться также X/Z, `range`, `height` и `flags`.

   Повторять спавн несколько раз: CE может менять положение предмета внутри области точки и его ориентацию. Изменение нескольких параметров одновременно затрудняет определение причины.

5. **Проверить результат другими предметами.**
   На исправленной точке проверить несколько подходящих типов и несколько повторных спавнов. Следить и за проваливанием, и за зависанием над полом. Для отдельной проверки физической коллизии можно поднять предмет и бросить его обратно; основной тест размещения выполнять через спавн CE.

6. **Сохранить и повторно проверить исправление.**
   Записать исходные и новые параметры точки, проверенные предметы и результат. Сохранить правку в `mapgroupproto.xml`, затем выполнить чистый повторный запуск по инструкции ниже.

Проблема может находиться в точке, геометрии или коллизии здания либо модели предмета. Успешная проверка одного предмета ещё не подтверждает исправность всех остальных.

## Экспорт и чистый повторный запуск

После изменения файлов CE:

1. Если точки редактировались в игре, выполнить **Diag Menu → Game → Central Economy → Loot Spawn Edit → Export Group**, пока миссия ещё открыта.
2. Полностью закрыть DayZ.
3. Перенести нужные изменения из экспорта в `mapgroupproto.xml` этой миссии. Экспорт находится в `storage_-1/export/`; для выбранного здания файл обычно называется `mapGroup_Land_Store_Street1.xml`.
4. Переименовать папку `storage_-1`, например в `storage_backup_01`. Для следующей резервной копии выбрать новое свободное имя.
5. Запустить `start_client.bat` заново.

CE создаст новую папку `storage_-1` из текущих XML. Старое состояние и экспорты сохранятся в резервной папке. В этой простой миссии переименование выполняется вручную.

**Внутри одного сеанса**, пока выполняются эксперименты через Diag Menu, переименовывать хранилище не нужно. Перед выходом необходимо экспортировать нужные изменения: они не заменяют входной XML автоматически.

## Основные файлы

| Файл | Что определяет |
|---|---|
| `db/types.xml` | Предметы, их количества и условия допуска к спавну |
| `mapgroupproto.xml` | Контейнеры, локальные координаты и параметры точек лута |
| `mapgrouppos.xml` | Положение и поворот группы лута в мире |
| `objects.json` | Положение и поворот самого здания через Object Spawner |
| `cfggameplay.json` | Подключение `objects.json` через `WorldsData.objectSpawnersArr` |
| `db/economy.xml`, `db/events.xml`, `db/globals.xml` | Включение и общие правила работы CE |
| `storage_-1` | Сгенерированное состояние CE и экспорты текущего запуска |
| `logs` | Журналы игры, заданные в `start_client.bat` |

## Если здание переносится или поднимается

Менять положение здания в `objects.json` и группы CE в `mapgrouppos.xml` согласованно. Например, при подъёме на 10 м увеличить Y на 10 в обоих файлах. Локальные координаты точек в `mapgroupproto.xml` при таком переносе сохраняются.

Для сравнения сохранять одинаковый поворот и масштаб здания. Воздушный тест помогает проверить коллизию модели отдельно от поддержки землёй; рабочее размещение здания также следует проверить.
